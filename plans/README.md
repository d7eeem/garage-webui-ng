## Findings considered and rejected

Recorded so nobody re-audits them.

- **Goroutine loop-variable capture in `backend/router/buckets.go:29`** — looks
  like the classic Go closure bug, is not. `backend/go.mod` declares `go 1.23.0`
  and Go 1.22+ gives each loop iteration its own variable. The closure is
  correct. (Plan 004 *does* rewrite this function, but for unbounded concurrency
  and nondeterministic result ordering — not for capture.)
- **The catch-all admin proxy injecting the cluster admin token**
  (`backend/router/proxy.go:23`) — this is the product. It is a Garage admin UI;
  proxying admin calls with admin credentials is the design, not a defect. The
  real finding is that it is unauthenticated by default, which plan 001 step 5
  addresses with a startup warning.
- **The bcrypt hash in `backend/.env.example`** — a documented placeholder in an
  example file, not a live credential. Not a secret leak.
- **`path.Clean(r.URL.Path)[1:]` in `backend/ui/ui_prod.go:25`** — no path
  traversal. `path.Clean` normalizes `..` before `fs.Stat`, and `http.FS`
  rejects escapes independently. `path.Clean` also always returns at least one
  character, so the `[1:]` slice cannot panic.
- **`COPY --from=alpine` with no matching build stage in the `Dockerfile`** —
  valid Docker: `--from` accepts an image name, so it resolves to `alpine:latest`
  and works. Only an unpinned-base nit, noted in plan 008's maintenance section
  and deliberately left out of scope there.
- **`strings.Split(AUTH_USER_PASS, ":")` truncating a hash containing `:`**
  (`backend/router/auth.go:25`) — bcrypt's alphabet is `./A-Za-z0-9` plus `$`.
  A `:` cannot appear in a bcrypt hash. Safe as written.
- **`useRevertChanges` ignoring its `version` argument**
  (`src/pages/cluster/hooks.ts:75-80`, called with `data.version + 1` at
  `nodes-list.tsx:114`) — the argument is dead, but Garage v2's
  `RevertClusterLayout` takes no version, so the hook is right and the caller is
  merely passing something unused. Cosmetic; not worth a plan.
- **`readableBytes` capping at `TB`** (`src/lib/utils.ts:22`) — a petabyte-scale
  value renders `"1.0 undefined"`. Real but currently unreachable for this
  project's users, and plan 002 pins the behavior with a skipped test that
  documents the gap. Extend the `sizes` array when someone has a PB cluster.
- **`readableBytes` divider inconsistency in the cluster node row**
  (`nodes-list.tsx:237` uses `1000`, `:246` uses the `1024` default) — capacity
  in decimal and free space in binary, side by side. Cosmetic; flagged so the
  next reader knows it was seen.
- **`window.confirm` for destructive actions** (`object-actions.tsx:38`,
  `nodes-list.tsx:104`, `keys/page.tsx:40`) — unpolished but functional, and
  commit `d1ad6a0` shows the maintainer is already iterating on confirmation
  wording. Not a defect. Plan 011's Q3 revisits it only in the context of bulk
  operations, where a native confirm genuinely stops being adequate.
- **`&& data?.version != null` after `window.confirm`**
  (`nodes-list.tsx:110-116`, `:118-125`) — if the version is null the confirm
  still appears and then nothing happens. A minor UX wart; not worth a plan on
  its own.
